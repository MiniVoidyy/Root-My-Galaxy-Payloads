# Support manifest v4 & the draft catalog

`support/targets-v4.json` is generated by `tools/refresh_manifest_v4.ps1`.
It contains two kinds of entries:

| status  | meaning                                                              |
| ------- | -------------------------------------------------------------------- |
| `stable`| Real, hardware-verified per-firmware payloads with SHA-256 checksums. |
| `draft` | Coverage metadata only. The app lists the device but never matches, downloads, or executes it. |

## Why drafts exist

The exploit binaries and the KernelSU stage are per-firmware-build. A firmware
that has not been built and verified on hardware must never be offered for
installation. Draft entries give the app catalog visibility into which
devices/kernels are targeted, while the app refuses any install until the
payload exists, is registered as `stable`, and passes checksum verification.

Each draft row is an exact model-set + exact `X.Y.Z` kernel version. Exact
matching means a device simply does not match until a payload is registered for
that precise line, so nothing unsafe can ever run as a "best effort".

## Promoting a draft to stable

1. Build the payload for one exact firmware (see `PORTING.md`), e.g.
   `make TARGET=pa3q-S908NKSU... release`, producing `src/build/.../artifacts/JBP4A/cve-2026-43499-app.so`.
2. Place or copy the artifacts under `artifacts/<device-build>/` and the
   KernelSU stage under `kernelsu/` so the script can see them on disk.
3. In `tools/refresh_manifest_v4.ps1`, flip the corresponding draft row from the
   device matrix to a stable entry (or add it to the stable section with the
   repository-relative artifact paths).
4. Re-run the generator, which size-checks and SHA-256-hashes every stable
   artifact from the local checkout. Failure to match disk == the generator throws.
5. Commit and push the new artifacts + manifest. Devices the payload does not
   exactly match keep matching nothing.

The root (`main`) branch of this repository is pinned by the app; the app
resolves the manifest at the `main` commit and downloads artifacts from exactly
that commit with checksum verification, so pushes are atomic from the app's
perspective.
